# Deploy and staging

## `Publish-Module` is the operator's, and only the operator's

**The agent never publishes.** No `Publish-Module`, no `nuget push`, no release
creation, no push to `main`, no tag — unless the operator runs it from their own
shell.

This is not a soft preference and there is no `-Force`, no `-WhatIf` rehearsal,
and no "just for testing" that changes it. Publication is irreversible in
practice: a package pulled from a gallery minutes later has already been mirrored
and cached, and a version number can never be reused.

What the agent does instead: **stage the artifact, verify it, and say it is
ready**, naming the exact command the operator would run and the values it needs.

```
Ready to publish. From your own shell:

    Publish-Module -Path ./output/PSAzureDevOpsGraph -NuGetApiKey <key> -Repository PSGallery

Verified: manifest 0.2.0, 15 exported commands, help topic present,
analyzer clean, 41/41 tests, coverage 82.88% (target 40%).
Not verified: nothing on the gallery has been contacted.
```

The one deliberate amendment to this rule is annotated tags on the target module
repository, and only when a pass prompt names the version — see
`decisions/0006-target-versioning-and-tags.md`. Everything else in the rule is
unchanged: no `main`, no `Publish-Module`, no tags anywhere else.

## What a publishable artifact contains

`output/<Name>/` is the whole deliverable. Nothing outside it ships, and nothing
in `src/` does.

```
output/<Name>/
  <Name>.psd1              copied from src/, not regenerated
  <Name>.psm1              GENERATED — concatenation of Private/** then Public/*
  en-US/                   culture directories, copied
    about_<Name>.help.txt
  <Name>.format.ps1xml     other root files from src/, copied
  <Name>.types.ps1xml
```

Four things about the generated psm1 are graded, each structurally rather than
by text match:

1. It says `auto-generated` (case-insensitive), so nobody edits it.
2. `$script:ModuleRoot = $PSScriptRoot` is a real **assignment**. Concatenation
   moves what `$PSScriptRoot` means, so assets must resolve from a variable that
   is the same under the build and under a dev loader.
3. `Export-ModuleMember -Function` is a real **call** listing every name in
   `FunctionsToExport` as string constants.
4. Functions defined in nested `Private/` subfolders are present as definitions.

**Culture directories must be copied** or `Get-Help` will not find `about_`
topics. This is the most commonly missed item, because the build works and the
tests pass without it.

**`output/` is never committed and never edited.** It is regenerated by every
build and wiped by `Clean`. Edits there vanish and mislead. A stale `output/`
also masks source edits — tests import from it, so build before testing.

## Prerequisites, verified before anything is staged

*Source: the `Dependencies` task in `PSModuleGraph.build.ps1`.*

A deploy step that assumes and proceeds is a deploy step that ships the wrong
thing quietly. Check, and fail naming what is missing.

- **Every declared `RequiredModules` entry resolves.** Without it
  `Import-Module` fails outright at the user's end, which is the first thing to
  know and the last thing a build notices.
- **The resolved version satisfies the declared constraint** — and check every
  constraint `RequiredModules` can express (`RequiredVersion`, `ModuleVersion`,
  `MaximumVersion`), not the one that happens to be written today. A requirement
  that stops being checked when its shape changes is a requirement nobody is
  checking.
- **The resolution is explicit and ordered**, never "whatever is already on
  `PSModulePath`". A build that passes because of what happened to be imported
  in the session is a build that says nothing. Look in a named list of places,
  in a stated order, and throw with a hint naming both:

  ```
  PSGraphRender could not be resolved. Found '../PSGraphRender' but no built
  module inside it. Run ./build.ps1 there first.
  ```

- **Print the resolved version.** It puts the fact next to the failure rather
  than three tasks away from it. A sibling checkout drifting three minor versions
  past its pin went unnoticed until an unrelated golden comparison broke.

## The deploy checklist

- [ ] `./build.ps1` exits 0 — analyzer clean, tests green, coverage at or above
      its declared target
- [ ] `output/<Name>/` holds the manifest, the generated psm1, culture
      directories, and every other root file from `src/`
- [ ] `Import-Module ./output/<Name>/<Name>.psd1` succeeds **in a clean process**
- [ ] `Get-Command -Module <Name>` returns exactly `FunctionsToExport`, same
      count and same set
- [ ] `Get-Help <Command>` returns a synopsis for every exported command
- [ ] `Get-Help about_<Name>` finds the topic
- [ ] `ModuleVersion` is the version being released, and no tag for it exists yet
- [ ] Every `RequiredModules` entry resolves at the declared version
- [ ] No artifact contains a credential — scan before staging, not after
- [ ] The publish command is written out for the operator, and not run
