# Pass 0035 — Instrument repair and the tf-003 kit

## Asked

Three things, in an order that is itself the argument: repair the comparator
before anything is measured with it (backlog 32), settle in writing whether
tf-003 reads pipelines from files or from the REST API (backlog 31), and then
author what a builder is handed — a brief and a seed that name no case, no
count, no mechanism and no expected shape, with the sanitization scanner as
the gate rather than my word for it. Harness only. No release.

## Done

- **Acceptance red first.** 7 of 7 failing, measured and recorded. The
  fixture-1 comparator suite measured at 15/15 at the same moment, because
  that is the number the repair must not move.
- **Stage 0** in `Compare-TfGraph.ps1`: id uniqueness asserted on both graphs
  before the first assignment into a dictionary. `DuplicateId` is its own
  category. Mutation 8 added to the mutator;
  `Invoke-TfDuplicateIdFalsification.ps1` falsifies both directions;
  `Invoke-TfSuite.ps1` runs both suites at pinned counts.
- **Decision 0014 amended**: pipeline definitions are outside the TF
  measurement surface. Mirrored into `docs/testing/`.
- **The tf-003 kit**: `evals/tf/BRIEF.md`, `evals/tf/seed/`,
  `Reset-TfTarget.ps1`, and a `-RuleSet Kit` for the sanitization scanner with
  a real second control.
- **Pins, docs, plan, verify.** Verification green; all four probes fire.

## Why

**Why the repair came before the kit, and not after.** Both were in the
prompt and either order would have produced the same files. But the kit exists
to be measured, and a measurement instrument that cannot see a class of defect
is worse than no measurement, because it produces a number. Repairing second
would have meant a window in which the pass had authored the thing to be
scored while knowing the scorer was blind.

**Why `DuplicateId` and not `ActualNodeCount -eq ExpectedNodeCount`.** Backlog
32 offered both. The count is the cheaper one and it is wrong in the case that
will actually happen: a graph with one node duplicated and one node missing
has the correct total and two defects. Uniqueness is the property; the count
is a proxy for it that fails precisely where a real producer fails.

**Why mutation 8 is not in the seven-mutation driver.** The other seven break
the graph under test. A duplicated id is the same defect whichever side
carries it, and the side that nobody checks is the *oracle* — which is exactly
the side that kept the control green. A driver that could only mutate the
graph under test would have left half the repair untested, and the untested
half is the half the finding was about. It also keeps
`plans/0030-release/mutations.txt` diffable, but that is a convenience, not
the reason.

**Why the fixture rule set could not gate the brief.** A fixture is a
Terraform repository that has to read as an ordinary configuration, so the
word *graph* in it is a leak. A brief is a customer's statement of the job,
and it has to say graph, producer, contract and unresolved — a brief that
could not name its own deliverable would not be a brief. The two documents
have opposite obligations, so they get different rule sets, and the report
says loudly that neither contains the other: Kit drops a category and adds
one, and on counts it is *stricter*.

**Why backlog 31 was closed by narrowing.** Creating four pipeline definitions
in fixture 2 would have bought parity in a dimension no oracle reads — checked
rather than assumed: zero pipeline nodes in either oracle, six node types
each, all HCL — at the cost of a new decision, three pushes to a frozen
fixture, and a re-freeze. The amendment also forecloses the cheap path later,
which is the half that matters: the objects existing is not a reason for a run
to read them.

## Learned

**A probe that does not fire is a finding, not a broken probe.** This whole
pass exists because pass 0034 wrote a probe expecting the control to go red,
watched it stay green, and wrote down what it actually proved rather than
adjusting it until it agreed. That is the entire method working, once, in the
one place it is easiest to skip.

**A dictionary is a deduplicator.** `$byId[$node.id] = $node` is the most
ordinary line in the file and it silently discards the earlier entry, so a
duplicated id deleted itself on both sides and the two sides agreed. The
evidence was printed the whole time — `expected: 99 node(s)` directly above
`actual: 100 node(s)`, verdict clean underneath. A verdict a reader trusts
is a header a reader does not read.

**`git commit --date=` pins only the author date.** Found by my own claim
being false. `Reset-TfTarget.ps1` said its commit SHA was reproducible; two
resets a second apart produced different commits, because the committer date
still comes from the wall clock. The reproducibility check inside the script
had agreed with the claim — because it ran the two resets back to back, inside
the same second. The check now reads the stamps back rather than comparing two
SHAs made at the same instant. **An equality check between two things made at
the same moment is not a test of determinism.** LEDGER item 33.

**A rule that exists is not a rule that was applied.** The root
`.gitattributes` already carried `evals/functional/seed/** text eol=lf`, with
a comment explaining exactly why. `evals/tf/seed/LICENSE` still resolved to
`text=auto` with no `eol`, so a fresh Windows clone would have checked it out
CRLF and produced a different tree from the one about to be pinned. Caught by
running `git ls-files --eol` before writing the pin, not by remembering the
rule. LEDGER item 34.

**The gate found three leaks in my own first draft, and the prose was fixed
rather than the rules.** `deliberately` in the seed's `.gitattributes`,
`exactly the kind of tool` in the brief, and `from one repository into
another` — a count of repositories in the middle of a sentence about
something else. Two of the three were harmless in substance. Editing the
pattern to let them through is how an allowlist stops being a gate, and the
cost of rewriting three phrases was about a minute.

**`pwsh -File` flattened `-Path a,b` into one token,** exactly as LEDGER item
15 says it does, the first time the new parameter was used. The item was
written in pass 0028 and read in pass 0035 only after the error. Knowing a
hazard is written down is not the same as reaching for it.

## Capability

The Terraform measurement line can now be run. The instrument detects a class
of defect it could not see before, in both directions; the question of what
tf-003 reads is answered in a decision rather than in a plan; the kit exists,
is pinned two ways, and is gated by a scanner with a real second control; and
the reset that starts a run refuses six ways of pointing it at something that
is not scratch.

What it still cannot do: score fixture 2 case by case. `Test-TfFixtureCase.ps1`
is fixture-1 specific and has no counterpart, backlog 29, and tf-003 needs one
before it can report anything finer than a difference count. That was not in
this pass's scope and half-generalising it would have produced a scoring
script that is neither fixture's.

tf-003 is next, and this session cannot be the one that runs it.
