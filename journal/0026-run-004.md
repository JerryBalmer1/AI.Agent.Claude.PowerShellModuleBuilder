## Why

**Three parallel jobs, but the conformance job builds its own clone.** The
prompt asks for parallelism; `RequiresBuild` reads `output/`, which the build
job's `Clean` deletes. Sharing one working tree would have made the conformance
number a race artifact. Cloning discharges spot-check 1 as a by-product, which is
why that was preferred over serialising the two.

**`commands/build.md` step 1 was declined, not obeyed.** It instructs reading
`evals/conformance/Conformance.Tests.ps1`; the Phase 1 allowlist forbids it. The
protocol wins over the plugin, and the consequence is stated rather than
smoothed over: the conformance score measures skill-fidelity, with the
assertions unread.

**The credential scan was tightened, and the tightening had to be defended.** It
first failed on the README's `$env:AZDO_PAT = '<your token>'`, the `about_`
topic, a labelled test dummy, and its own probe literal. Rewriting it to judge
the assigned *value* rather than the variable's *name* is the kind of change that
turns a check into decoration, so `P3c` was added to assert it still tolerates
all four placeholders while `P3b` asserts it still catches a real token — the
scan has to be provably neither vacuous nor a nuisance.

**Rejected: lowering the coverage target.** The 70% target was set before the
tests were written and coverage landed at 94.61%. When the gate was found to be
inoperative it would have been cheaper to leave it, since every build was green
either way. Falsifying it at 99% cost one build and is the only evidence the fix
did anything.

## Learned

**A gate can be structurally present, assert-ably present, and still incapable
of failing.** `powershell-module-build`'s `Test` task template omits
`Run.PassThru`, so `Invoke-Pester -Configuration` returns nothing, `$percent`
comes out 0, `$target` comes out `''`, and `0 -lt ''` is false. The build printed
`Line coverage: 0% (target %)` and exited 0 four lines after Pester printed
`Covered 90.31% / 70%`. The conformance suite scored this repository 57/57
*including* the assertion "throws on coverage below target rather than only
reporting it" — which is true, and tests that the gate exists rather than that it
can fire. The same omission makes the `PreTag` guard throw on every run. One
missing line, two gates, in opposite directions. This is F-1 and it is the most
serious thing this run found.

**Grouping differences by mechanism before reading the count is worth more than
the count.** 26 looked like a broken producer. It was three one-line conventions
and one real defect, and the real defect was the single difference — exactly what
`producer-contract` predicts, verified here rather than assumed.

**The plugin teaches the absent-means-not-stated principle and then undercuts it
by example.** `azdo-graph-assembly` shows one node and one edge with every
optional field present and says nothing about when each is absent. I applied the
same argument — "`kind` already carries it" / "`ref` already carries it" — to
`refKind` and not to `alias`, got one right and one wrong, and paid 8
differences for the inconsistency.

**A skill that names a symptom converts an opaque failure into a two-minute
fix.** The `-ModuleName` mock ran in module session state where the test file's
`$script:` variables do not exist, and it surfaced as `'break' or 'continue'
escaped from your code` against a whole container with 21 blank failure
messages. `powershell-module-test` names that exact symptom and says to call the
code under test directly; doing so produced `CommandNotFoundException:
Get-AzDoCachedYaml` immediately. The underlying cause — `.GetNewClosure()`
rebinding a scriptblock to a fresh dynamic module where module-private functions
vanish — is in no skill, and should be.

**My own README example was wrong before it was run.** Written from expectation,
two of three columns incorrect, caught only by running the module — which is the
failure `powershell-module-docs` names in as many words. Writing the rule down
did not stop me doing it; running the command did.

**A verify script gets the same scrutiny as the thing it verifies.** Two defects
in it: `pwsh -File` cannot bind an array parameter, and the credential scan was
scanning for a variable name rather than for a secret. The second would have
been "fixed" by deleting the check.
