# 0032 — the control finally ran, and it did not say what the README says

Backlog 17 has been the highest-value single run remaining since pass 0029 named
it. Run 003 was plugin-off but forbidden to iterate; runs 004–006 were plugin-on
with three iterations each. So the with/without table compared a first shot
against a converged result and called the difference the plugin. This pass ran
the missing cell: plugin-off, same seed, same brief, same model pin, same
three-iteration budget.

**It converged. 12/12, zero differences, in one iteration.**

That is the finding, and it was going to be printed either way.

## What the numbers actually say

The blind run's first shot was **6/12 with 14 differences**. Every plugin-on
first shot was **1/12 with 26**. The blind run was *closer* before anyone fixed
anything, because all three plugin-on runs omitted `repo` from `pipeline` nodes
and this one did not — it took that from one clause of the brief, *"each with
the repository and path its YAML lives at"*.

Strip those fifteen differences out of run 003's twenty-nine and what is left is
this run's fourteen, mechanism for mechanism and count for count. Two blind
sessions, the same five mistakes, one property apart. Which is worth stating
carefully: it is one observation, and it is as consistent with variance between
two sessions as with anything about how the brief reads.

Where the plugin was unambiguous is conformance. Plugin-on: 33/33 at first shot,
every run, never lost. Plugin-off: 19/33 at first shot — *identical* to run
003's re-derived 19/33 — and 28/33 after spending two of three iterations on
nothing but house style. Build file name and task set, the generated single
`.psm1`, `Requirements.psd1`, analyzer settings, a test per exported command:
none of it is in the brief, none of it is in the fixture, and there was never any
route to it except reading the house's own documents.

So the honest shape is: **the plugin buys shape, not correctness.** The
dependency computation was right first time in all four runs — zero missing
edges, zero wrong targets, both anchoring rules correct, the cycle terminated,
the diamond collapsed — whether the skills were readable or not.

## The part that took longer to write than the module

Three things make the headline weaker than it looks, and all three are in the
record because leaving them out would have made the record worse than useless.

**The prompt told the builder the answer.** Step 7 lists the four convention
mechanisms *with their counts* so that the run record can report against them,
and the prompt is on the Phase 1 read-allowlist. Three of the four recurred
anyway. The fourth is `repo`-on-`pipeline` — the one the headline turns on, and
precisely the one a leak would most plausibly have prevented. This run cannot
separate careful reading from having been told. Next control: mechanism list out
of the builder's prompt, into the scoring instructions.

**The conventions were readable — just not from the plugin.** `Compare-Graph`
prints the oracle's expected value for every wrong attribute. The exact thirty-word
`reason` string was read out of the diff and reproduced, not re-derived. The
step-7 phrasing "without the conventions being readable anywhere" is false as
written. What the control shows is that the conventions were not needed *in
advance*, which is a different and smaller claim.

**The fixture explains itself.** Reading it through the module — which the
protocol requires — returns YAML whose comments name each case and spell out its
trap. Every run, blind or not, has had that. It explains why the traversal is
always right first time and the conventions never are. It is not noted anywhere
in the ladder's records and it should be.

## A scoring rule that cannot be satisfied

Four `RequiresBuild` assertions read `output/`. `output/` is gitignored. The
protocol scores conformance in a clone that never runs the build. Those four can
never pass; their own failure message says *"run the build before the
RequiresBuild tag"*. Re-scored in one clone with the build run first, the same
commit gives 32/33 instead of 28/33.

28/33 is what this run reports, because that is the protocol. But the ladder
reported 33/33 with those assertions passing, so its conformance job saw build
output somehow — and run 005's README records a race where `Clean` deleted
`output/` while the tag was reading it, which means its jobs shared a tree.
**The ladder's conformance numbers may not all have been produced the same way.**
Comparing 28 against 33 overstates the gap by four. That wants resolving before
anyone quotes the comparison.

## Two bugs the oracle never saw

`Get-AzDoRepository` read `$repo.defaultBranch` directly. A repository with no
commits has no such property — not a null one — so StrictMode threw and the
pipeline swallowed it per object: four repositories returned where five exist,
with an exception on the console and no gap in the output. Caught by counting,
on the first live query.

That is the module's own reason for existing, one level up: a thing that is
missing looking exactly like a thing that is fine. It went into the run's
findings as a defect and into the tests as a mock whose third repository omits
the property, because one that sets it to `$null` does not reproduce the failure.

The second was `Join-Path (Get-Location) $Path` on an already-rooted path,
producing `C:\here\C:\there`. Every use in the run passed a relative path, so it
never fired; the first absolute path came from `$TestDrive` in tests written to
satisfy a conformance assertion about exercising every exported command. Those
tests were written to make a number go up and they found a real defect in the one
command the fixture walk could never reach.

## What is queued and what is not

The README's with/without section now claims more than four runs support. The
sentence it will need is drafted in the run record. It was **not** applied: the
release surface is tagged, and rewriting it is a pass that owns it.

Probe D of the verify script failed the first time it ran — the planted token was
fifty characters, not fifty-two, and the probe used a different pattern from the
check it was meant to falsify. Both fixed, pattern now defined once. A probe that
cannot fail proves nothing, and this one proved it could by failing.
