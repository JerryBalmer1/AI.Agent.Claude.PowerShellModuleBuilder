## Why

**The stop was the correct behaviour and not caution.** The eight missing
assertions were the eight that pin provenance — plugin SHA, model version,
session identifier, seed/brief/target, wall-clock, build, conformance
denominator. An agent that writes those for itself can omit one and pass its own
grading. Rejected: reconstructing them from run 004's test, whose `It` names were
readable. A blind Phase 1 runs once per session, and a wrong guess would not have
surfaced until task 8, after the branch was pushed.

**The conformance job was re-scored from a fresh clone, and the raced number was
kept rather than replaced.** Running the three scoring jobs in parallel put
`build.ps1`'s `Clean` against the `RequiresBuild` tag's read of `output/`, and
first-shot conformance came back 51/56 with all five failures in the *generated
module* assertions. Rejected: silently substituting the clean number. The
iteration table states the correction in the open and both transcripts are
committed, because a first-shot cell that changed after being seen has to show
why.

**One read outside the allowlist was declared rather than avoided.** The schema
requires `organisation` and `project`, `azdo-rest` forbids discovering them, and
nothing on the allowlist supplies them. A `grep -o` against
`evals/functional/AzdoClient.ps1` returning only `jlbalmerjr1` and
`ClaudeTesting` was taken and itemised. An address is not an answer; the
alternative was not running Phase 1 at all.

**The oracle was matched, not argued with.** Three of the four first-shot
mechanisms were choices between readings the documents both permit, and the
oracle settled them. `reason` is the exception and is recorded as a finding
rather than a lesson: matching a hand-written sentence is fitting to this
fixture, not a capability.

## Learned

**A fixed instruction set reproduces its defects exactly.** All eight of run
004's findings recurred, at the same sites, in a session that had not read them.
Two runs, same four first-shot mechanisms, same counts, same single real defect,
same one iteration, same final scores. That is the strongest evidence the ladder
has produced that these are properties of the plugin rather than of a session —
and it means run 006's value is now mostly in whether it breaks the pattern.

**Run 004 predicted the one thing that differed.** Its F-5 said the next reader
would hit the `powershell-yaml` fork and might go the other way, "and then the
two runs differ for a reason that is not the model." Run 005 went the other way.
Conformance scored 33/33 either way, so the instrument cannot see the only
source-level disagreement between the two builds.

**A comma-separated array does not survive `pwsh -File`, and it cost this pass
three times.** `-Task Build,Test` became one task name and aborted InvokeBuild;
the same shape made both gate falsifications look red while proving nothing;
the same shape then made `-Tag Universal, Repository, …` fail a `ValidateSet`
inside `verify.ps1`. The first occurrence is the dangerous one: a falsification
that is not itself checked is the hazard it exists to prevent, one level up.
Caught by reading the log instead of the exit code.

**Pass 0025's denominator earned itself here.** Run 005 ships no culture
directory, so one conformance case is inapplicable and skipped. At `cases-run`
the two runs read 57 and 56 and are incomparable; at `cases-defined` they read
33 and 33 and are. This is the first target to move that number.

**Run-record commit subjects leak scores into every future blind session.**
`git log` at preconditions is unavoidable, and `ed7280f`'s subject carries run
004's totals. Recorded as backlog item 14 with a message convention, because no
session can fix it from inside.

## Capability

The ladder can now state, with two independent measurements, that the plugin
produces the same four first-shot mechanisms and the same final scores at fixed
inputs — and can name the one decision that varies between sessions and is
invisible to the score. `verify.ps1` can disprove a run record from a fresh
clone, including regenerating the graph live and comparing it, and can prove its
own checks are falsifiable.
