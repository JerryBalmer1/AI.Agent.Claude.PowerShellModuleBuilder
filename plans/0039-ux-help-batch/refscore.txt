WHY THIS IS BUCKET B AND NOT BUCKET A.

Bucket A is a defect in the grader. Bucket B is a real property of the target.
Every one of these is a real property: the functions genuinely have no examples,
and the parameter set genuinely is not demonstrated. A reader of that module is
worse off for it. The assertions are behaving correctly.

The reason the failures are DECLARED rather than fixed is the boundary, not
charity: the commit predates the rule, and editing a scored commit to satisfy an
assertion written after it would destroy the only thing the commit is good for -
being a fixed point that earlier numbers were taken against. The rule from
METHOD applies in both directions here: never weaken an assertion because a
target fails it, and never rewrite a target because an assertion is new.
